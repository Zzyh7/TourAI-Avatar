## 1. 产品概述

### 1.1 产品定位

**景区导览AI数字人 TourAI** 是一款面向景区游客的智能导览产品。通过 **Live2D 小僧数字人** + **实时语音对话** + **RAG 知识问答** + **拍照识景** + **个性化推荐**，为游客提供沉浸式、智能化的景区游览体验。

### 1.2 核心能力

| 能力 | 说明 |
|------|------|
| 👤 **Live2D 数字人** | 小僧角色，4 表情状态（中性/开心/思考/播报），背景可自定义 |
| 🗣️ **RAG 智能问答** | FAISS + BM25 + RRF 混合检索 + DeepSeek，275条景区知识库 |
| 🎤 **语音对话** | DashScope Paraformer STT + Edge-TTS 合成 |
| 📷 **拍照识景** | 通义千问-VL 多模态识别 + RAG 知识增强 |
| 📍 **地图服务** | 高德 MCP 15 工具，POI/天气/路线/GPS触发 |
| 🧭 **个性化推荐** | 家庭游/文化深度游/休闲游/祈福游 |
| 📊 **数据运营** | 12 模块管理后台，满意度追踪，答不上率统计 |

### 1.3 用户端页面

| 页面 | 地址 | 说明 |
|------|------|------|
| 暗黑电影级首页 | `:8000/web` | 轮播Hero + 智能导览卡片 + 场景叙事 |
| 游客端 | `:5173` | 三栏布局：推荐卡片 + Live2D + 对话框 |
| Live2D 数字人 | `:3000/sentio` | 小僧对话主界面（文字+语音+后台） |
| 管理后台 | `:5174` | 12 模块后台 |

## 4. 核心模块设计

### 4.1 Multi-Agent 导览系统

```
GuideAgent (总控，"小僧")
  ├── query_weather     → WeatherAgent     → MCP maps_weather
  ├── search_attraction → AttractionAgent  → MCP maps_text_search
  ├── search_route      → RouteAgent       → MCP maps_direction_*
  └── search_knowledge  → RAG 混合检索器   → FAISS + BM25
```

- **GuideAgent**：LangGraph ReAct Agent，拥有人设 prompt 和工具路由
- **SpecialistAgent**：领域专家子 Agent，最小权限原则，各只持有相关工具
- **设计模式**：门面模式 + 装饰器模式

### 4.2 RAG 知识库系统

```
文档上传 → 多格式解析 → 递归分块(500/50) → BGE 向量化 → FAISS + BM25 双索引

用户提问 → FAQ 精确匹配(0.85) → FAISS + BM25 双路检索 → RRF 融合(k=60) → 阈值检查(0.35) → DeepSeek 生成
```

核心文档：[backend/rag_system/](backend/rag_system/)

### 4.3 Live2D 数字人系统

集成 **AWESOME-DIGITAL-HUMAN Live2D v3.0** 开源框架：

| 组件 | 说明 |
|------|------|
| **Live2D Web** (`:3000`) | Next.js 前端，小僧角色渲染 + 对话 UI |
| **Live2D API** (`:8880`) | Python API，ASR/TTS/Agent 编排 |
| **TourAITTS 引擎** | 调用 TourAI `/api/tts` 接口 |
| **DashScope ASR 引擎** | 调用阿里百炼 Paraformer |
| **OpenAI Agent** | 调用 TourAI `/v1/chat/completions` |

音色通过管理后台实时配置，数字人前端通过 postMessage 同步。

### 4.4 TTS 语音合成

- **引擎**：Edge-TTS（默认）/ 豆包 Seed-TTS-2.0（可选）
- **流程**：SSE 流式生成 → 句末检测(`。！？`) → 并行 TTS 合成 → 前端音频队列播放
- **首句优化**：逗号处分块（min_chars=12），首音延迟 < 2s

### 4.5 STT 语音识别

- **引擎**：DashScope Paraformer（阿里百炼）
- **前端**：AudioContext 16kHz 单声道录音 → WAV 编码 → POST `/api/stt`
- **回退**：浏览器 Web Speech API（需 VPN，国内不可用）
- **Live2D 端**：直接通过 Live2D DashScope ASR 引擎调用

### 4.6 MCP 地图服务

- 高德 MCP Server（SSE 传输），15 个工具
- 5 个领域：`poi` / `weather` / `route` / `around` / `geo`
- 单例模式 `McpClientManager`，懒加载 + 缓存

### 4.7 多模态拍照识景

```
拍照 → Canvas 压缩(1024px) → base64 → 通义千问-VL 识别 → RAG 增强 → DeepSeek 口语化讲解
```

### 4.8 情感分析与满意度

- **LLM 情感分析**：分析用户消息情感（正面/中性/负面），默认偏向正面
- **显式满意度识别**：关键词检测"我很满意"/"我不满意"等
- **答不上率统计**：检测助手回复中的"不太了解"等标志
- **负面对话记录 API**：`/api/admin/stats/negative-conversations`

数据库字段：`sentiment`（情感）、`satisfaction`（满意度）、`is_unanswered`（答不上）

### 4.9 管理后台

12 个功能模块：

| 模块 | 说明 |
|------|------|
| 📊 数据大屏 | 交互量/满意度/答不上率/情感分布 |
| 🏛️ 景点热度 | 热门景点排行 |
| 📈 时间对比 | 时段趋势对比 |
| 💬 问答分析 | 回答准确率/用户满意度 |
| 👤 游客画像 | 人口统计/行为特征 |
| 🎯 游客分层 | RFM 模型分层 |
| 😞 负面反馈 | 负面对话记录与追踪 |
| 💬 常用对话 | 预设 Q&A 管理 |
| 📝 会话记录 | 完整对话回溯 |
| 📚 知识库文档 | 文档上传/索引管理 |
| 🏛️ 景点管理 | GPS 坐标/讲解内容 |

## 8. 部署架构

### 8.1 本地开发

```bash
# 一键启动（start.py）自动启动：
# - 后端 FastAPI :8000
# - 游客端 Vite :5173
# - 管理后台 Vite :5174

# Live2D 手动启动：
cd live2d && python main.py          # :8880
cd live2d/web && pnpm dev --port 3000 # :3000
```

### 8.2 生产环境

```yaml
# docker-compose.yml
services:
  backend:
    build: .
    ports: ["8000:8000"]
    volumes:
      - ./data:/app/data
      - ./.env:/app/.env
    command: uvicorn backend.main:app --host 0.0.0.0 --port 8000
```

前端建议 nginx 静态部署或 Vite preview。

### 8.3 环境变量

| 变量 | 必需 | 说明 |
|------|------|------|
| `DEEPSEEK_API_KEY` | ✅ | 大模型 |
| `DASHSCOPE_API_KEY` | ✅ | 多模态 + 语音识别 |
| `AMAP_API_KEY` | ✅ | 高德地图 |
| `DOUBAO_TTS_API_KEY` | ❌ | 豆包 TTS（不填用 Edge-TTS） |

## 9. 安全性设计

| 方面 | 措施 |
|------|------|
| **API Key** | `.env` 加载，不硬编码 |
| **CORS** | 限制 `localhost:5173/5174/3000/8000` |
| **SQL 注入** | SQLAlchemy ORM 参数化查询 |
| **文件上传** | 白名单校验，限制类型 |
| **反 hallucination** | RAG 阈值兜底 + Prompt 严禁编造 |
| **输入校验** | Pydantic BaseModel 自动校验 |
